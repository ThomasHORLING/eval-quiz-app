# J2 — Sécurité des images

Outil : Trivy (conteneur `aquasec/trivy`, version X.Y.Z), commande :
`trivy image --scanners vuln <image>` — mêmes options avant/après.
Rapports bruts : `preuves/J2/`.

## Résultats
| Image | Avant | Après |
|---|---|---|
| frontend | 4 MEDIUM (OS) | 0 |
| backend — OS Alpine | 11 (7 MEDIUM, 4 LOW) | 0 |
| backend — Node | 21 (6 HIGH, 14 MEDIUM, 1 LOW) | 2 MEDIUM |
| CRITICAL | 0 | 0 |

## Analyse et corrections
| Origine | Constat | Correction |
|---|---|---|
| npm, yarn et corepack embarqués dans `node:24-alpine` | 19 des 21 vulnérabilités Node, dont les 6 HIGH (undici, brace-expansion, ip-address…). Outils inutiles une fois l'application lancée | Build multi-stage : `npm ci` dans un étage `deps`, suppression de npm, yarn et corepack dans l'image finale |
| Paquets Alpine (OpenSSL, zlib, libexpat) | Correctifs publiés mais absents de l'image de base | `apk upgrade --no-cache` |
| Nginx / Express | Versions révélées (`Server: nginx/1.31.10`, `X-Powered-By: Express`) | `server_tokens off` et `proxy_hide_header X-Powered-By` dans `nginx.conf` |

## Vulnérabilités résiduelles
- `glob` et `minimatch` (MEDIUM, déni de service via motif glob malveillant) : dépendances indirectes de `resend` (via `js-beautify`). Jamais alimentées par des données utilisateur, donc non exploitables ici. Les corriger impose un changement de version majeure hors du périmètre « pas de modification métier ». **Risque accepté**, à revoir lors d'une mise à jour de `resend`.

## Compromis
- `apk upgrade` améliore la sécurité mais rend le build dépendant de la date de construction ; la CI reconstruit à chaque PR.
